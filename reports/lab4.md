# 第六章实验报告：文件系统与硬链接

## 一、功能总结

实现 fstat、linkat、unlinkat，支持查询文件状态、为同一 inode 创建多个名字及删除目录项；区分硬链接数与打开文件对象数，在链接与打开引用均消失后回收数据块和 inode。迁移时间、内存映射、spawn、优先级和 Stride 调度，适配从 easy-fs 加载程序。

## 二、实现说明

### 1. 文件状态查询

为 File 接口增加默认的 stat 方法，不支持状态查询的文件返回 None。OSInode 实现该方法，返回设备号、inode 编号、文件类型和链接数；预留字段全部初始化为零。inode 编号根据 inode 区起始块、实际块号和块内偏移计算。链接数通过扫描根目录中指向同一 inode 的非空目录项得到，适用于本实验的单层目录结构。

sys_fstat 检查文件描述符并取得文件对象，释放进程内部数据的借用后获取状态，再通过用户缓冲区地址转换按字节复制，支持结构体跨页。无效文件描述符或不支持状态查询时返回 -1。用户指针转换复用框架接口，未实现针对任意非法指针的完整访问验证。

### 2. 硬链接

linkat 查找旧名字对应的 inode，检查新名字后追加一个指向同一 inode 的目录项，不复制文件内容，不另分配 inode。拒绝旧名字不存在、名字相同、新名字已存在、为空或超过 27 字节等情况。通过扫描目录计算链接数，能够反映新增的名字。

### 3. 删除与资源回收

unlinkat 找到指定目录项后将其清空；目录查询与列表跳过空项。目录项所占的槽位暂不压缩，也未复用空槽，因此大量重复创建和删除会使目录继续增长。

内核使用 OPEN_INODES 按 inode 编号记录打开文件对象数量。每次构造 OSInode 时增加计数，在该对象的最后一个 Arc 引用消失、触发 Drop 时减少计数。fork 共享的文件对象由 Arc 管理，不因复制描述符而重复创建计数项。打开数量与硬链接数量相互独立。

删除名字时，若链接数为零且不存在打开对象，则立即回收；若文件仍打开着，则保留数据，等最后一个打开对象释放时回收。reclaim 清空文件大小并回收数据块，随后清除 inode 位图中的占用标记，最后同步缓存。该机制面向当前单核框架，不代表已具备多核并发与断电恢复能力。

### 4. 前序功能迁移

保留本章文件描述符表及基于文件系统的程序加载流程，迁移 sys_get_time、mmap、munmap、优先级设置和 Stride 调度。spawn 改为先通过 open_file 读取可执行文件内容，再建立子进程及父子关系，不再依赖第五章的内置程序查找函数。

## 四、第六章问答

### root inode 的作用，以及损坏后的影响

root inode 是根目录的元数据入口。在本实验中，编号为 0 的 inode 表示根目录。它记录根目录的大小及目录数据块位置；这些数据块中的目录项保存文件名和对应的 inode 编号，文件系统据此完成名称查找、程序加载及目录遍历。

若根目录的大小、数据块索引或目录项内容损坏，名称到 inode 的对应关系可能丢失或错误，导致文件无法打开、列表异常、程序无法加载，甚至触发断言或错误访问。文件自身的数据块不一定已经损坏，但正常的按名访问路径可能已失效。

root inode 不等同于超级块。超级块描述文件系统整体布局，而根目录 inode 描述根目录本身。当前 easy-fs 不提供日志恢复或自动修复机制，不能假定此类损坏能够自动恢复。

## 五、第七章问答

本节为按指导书要求随第六章提交的概念问答，不表示在 ch6 分支中额外实现了第七章管道功能。

### 1. pipe 的实际应用

在 Linux 终端中执行：

~~~bash
cat notes.txt | wc -l
~~~

shell 创建管道，将 cat 的标准输出连接到管道写端，将 wc 的标准输入连接到读端。cat 读取文件并写入字节，wc 读取字节流并统计换行符数量。这里 wc -l 统计的是换行符数，文件最后一段没有换行符时，不一定等于人所理解的文本行数。

父子进程在继承描述符后应关闭自己不使用的管道端，否则即使生产者已经结束，残留的写端引用也可能使读取方无法观察到 EOF。管道缓冲区有限，读写方还需要在数据不足或空间不足时等待或让出执行机会。

### 2. 更易用的多进程通信机制设计

可设计按名字或标识符访问的内核消息队列。进程创建或打开队列后，获得本地句柄；发送时指定目标队列和消息，接收方从自己的队列取出消息。一个队列可由多个进程发送或接收，不必为每对进程单独建立管道。

消息包含发送者标识、类型、长度和载荷，保留消息边界。内核为队列设置容量与权限检查；队列空或满时，按调用选项阻塞、让出执行机会或返回非阻塞错误。对于较大数据，可以让消息传递受权限控制的共享内存句柄，减少复制。

还需规定队列关闭、删除、进程退出及等待者唤醒规则，并限制每进程与系统总体资源使用量。相比逐对建立管道，这种设计简化了多生产者、多消费者场景，但仍需明确消息的接收与分发策略。该方案为设计说明，本次未实现。
