# 第三章实验报告：多道程序与分时多任务

## 一、功能总结

本实验实现了 sys_trace 系统调用，支持读取一个字节、写入一个字节，以及查询当前任务的系统调用次数。在任务控制块中增加独立的计数数组，并在系统调用分发前更新计数，使本次查询也计入统计。对于不支持的操作或超出计数数组范围的查询，返回 -1。

## 二、实验环境与运行结果

实验环境为 Ubuntu 22.04（WSL2），使用 nightly-2024-05-02 Rust 工具链、QEMU 8.2.2 和仓库附带的 RustSBI 0.4.1。

执行 `make -C os run BASE=2` 后，观察到：

- `Test trace OK!`
- `Test sleep1 passed!`
- `Test sleep OK!`
- `All applications completed!`

使用与仓库 CI 相同固定版本的官方检查器进行本地评测，结果为 7/7，检查器退出码为 0，报告文件检查通过。GitHub Actions 和成绩同步尚未验证。

## 四、简答题

### 1. 用户态执行非法操作的现象

本地运行中，非法地址访问触发 PageFault，另外两个 bad 测例触发 IllegalInstruction，内核终止对应应用并继续运行其他任务。使用的固件为 RustSBI 0.4.1。

本实验使用 RustSBI 0.4.1，运行三个 bad 测例后，观察到以下现象：

1. `ch2b_bad_address` 尝试向地址 `0x0` 写入一个字节。内核输出 `PageFault in application`，并终止该应用。
2. `ch2b_bad_instructions` 尝试在 U 态执行用于特权态返回的 `sret` 指令。由于权限不足，触发非法指令异常，内核输出 `IllegalInstruction` 并终止该应用。
3. `ch2b_bad_register` 尝试在 U 态通过 `csrr` 读取 S 态寄存器 `sstatus`，同样触发非法指令异常，内核终止该应用。

上述应用出错后，内核继续调度其他任务，后续程序仍能正常输出。这说明用户应用中的非法操作能够被捕获，并由内核处理，而不会直接终止整个系统。

### 2. Trap 进入与返回过程

结合 `os/src/trap/trap.S`，逐项回答：

- 进入 __restore 时，sp 指向什么？该函数在哪两种情况下使用？

刚进入 `__restore` 时，`sp` 指向当前任务内核栈中的 TrapContext 起始位置，其中保存了返回用户态所需的寄存器和控制状态。
`__restore` 有两种使用场景：一是首次运行用户程序时，恢复内核预先构造的初始上下文；二是用户程序因系统调用、中断或其他陷阱进入内核后，恢复保存的上下文，使程序继续运行。

- sstatus、sepc、sscratch 恢复了哪些状态？

sstatus 保存返回时所需的控制状态，其中 SPP 字段决定执行 sret 后返回的特权级；返回用户态时，SPP 应为 0。sepc 保存用户程序恢复执行的位置，供 sret 跳转使用。用户栈指针先恢复到 sscratch，随后通过交换 sp 与 sscratch，完成从内核栈到用户栈的切换。

- 恢复通用寄存器时为什么跳过 x2 和 x4？

`x2` 是栈指针 `sp`。恢复现场期间，内核仍需通过它访问 TrapContext，因此不能提前将其恢复为用户栈指针。用户栈指针已暂存在 `sscratch` 中，待其他寄存器恢复后，再通过交换指令恢复到 `sp`。
`x4` 是线程指针 `tp`。本章应用未使用该寄存器，因此当前实现省略了它的保存和恢复。这是本章实现的简化，并不意味着所有操作系统都可以忽略它。

- __restore 中交换 sp 与 sscratch 后，两者分别保存什么？

在 __restore 中，执行交换指令之前，sp 已经通过 addi 回到当前任务的内核栈顶，sscratch 中保存着用户栈指针。
执行 csrrw sp, sscratch, sp 后，sp 保存用户栈指针，sscratch 保存当前任务的内核栈顶。这样既为返回用户程序准备好了栈，也保留了下次进入内核时需要使用的内核栈位置。

- 哪条指令完成返回用户态？为什么会返回 U 态？

__restore 中通过最后的 sret 指令完成特权级切换。
执行 sret 时，处理器根据 sstatus 中的 SPP 字段确定返回的特权级，并跳转到 sepc 指定的位置。本实验返回用户程序时，恢复的 SPP 为 0，因此处理器进入 U 态，从用户程序的对应位置开始或继续执行。

- __alltraps 中交换 sp 与 sscratch 后，两者分别保存什么？

用户态进入 __alltraps 时，sp 仍保存用户栈指针，sscratch 保存当前任务的内核栈顶。
执行 csrrw sp, sscratch, sp 后，sp 指向内核栈顶，sscratch 暂存用户栈指针。随后，内核在内核栈上分配 TrapContext 空间，保存寄存器及控制状态，为处理陷阱和恢复用户程序做好准备。

- 用户程序通过哪条指令触发系统调用、进入内核？

用户程序通过执行 `ecall` 指令触发系统调用。处理器产生来自 U 态的环境调用异常；在本实验的陷阱委托配置下，该异常进入 S 态，由 `stvec` 指定的 `__alltraps` 入口接管。内核保存用户程序的上下文后，调用陷阱处理函数，再根据系统调用编号执行对应操作。
这描述的是系统调用路径；定时器中断或其他异常也可能使用户程序进入内核。
